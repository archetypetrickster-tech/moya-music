# Обновления для пользователя

Начиная с 0.9.0 виджет проверяет новые версии раз в сутки и предлагает скачать и установить их в своём окне. После подтверждения он заменяет приложение и запускает новую версию. Ручное скачивание архива больше не требуется. Для перехода с 0.8.x один раз установите 0.9.0 обычным способом.

В настройках есть «Проверять обновления автоматически» и «Проверить обновления…». Внизу — версия приложения и ссылка на GitHub. Вход в Яндекс, история и настройки лежат вне приложения и сохраняются. Автовоспроизведение по умолчанию выключено. Обновления используют системное подключение macOS: прокси из настроек виджета относится к Яндекс Музыке.

# Подготовка выпуска разработчиком

Используется [Sparkle 2.10.1](https://github.com/sparkle-project/Sparkle/releases/tag/2.10.1). Сборка скачивает официальный архив по HTTPS, проверяет закреплённый SHA-256 и кэширует его в `~/Library/Caches/MyMusicBuild`. Framework копируется с сохранением символических ссылок. Лицензия — `Sparkle-LICENSE.txt`.

Версия и номер сборки задаются в `build.sh`. Увеличивайте оба, номер сборки должен строго расти.

1. Соберите и проверьте приложение.
2. Создайте пустую папку выпуска. При необходимости положите в неё `my-music-update.html` с краткими примечаниями. HTML-фрагмент встроится в подписанный feed; отдельные неподписанные страницы не используются.
3. Запустите `zsh Исходники/release-update.sh "/абсолютный/путь/Моя музыка.app" "/абсолютный/путь/выпуск"`. Скрипт не публикует файлы: он создаёт `my-music-update.zip` и подписанный `appcast.xml`.
4. Загрузите `my-music-update.zip` в GitHub Release с тегом `v<версия>`; имя файла и адрес должны совпадать с feed. Пользовательский установочный архив `my-music-macos.zip` публикуется отдельно.
5. Только после доступности файла скопируйте подписанный `appcast.xml` без изменений в `docs/appcast.xml` и опубликуйте Pages. Подпись проверяется перед чтением feed, подпись ZIP — перед распаковкой. Редактирование XML после подписи делает его недействительным: заново запустите `sign_update --account ru.ninesquares.moyamusic appcast.xml` из закреплённой дистрибуции Sparkle.
6. Проверьте установленную предыдущую версию через «Проверить обновления…».

Подготовка пользовательского ZIP должна сохранять символические ссылки в framework: используйте `ditto -c -k --sequesterRsrc --keepParent "Моя музыка" my-music-macos.zip`, а не упаковку с разыменованием ссылок.

## Ключи и собственный форк

Приватный ключ хранится только в Связке ключей автора, учётная запись `ru.ninesquares.moyamusic`, и не входит в Git или архив. В приложении находится только публичный ключ. Потеря приватного ключа при текущей локальной подписи потребует ручного перехода пользователей: заранее сделайте защищённую резервную копию средствами `generate_keys`, никогда не кладите её в проект или GitHub.

Для собственного форка создайте отдельный ключ через `generate_keys --account <ваш-id>`, замените `SUPublicEDKey`, `SUFeedURL`, bundle ID и адреса GitHub в `build.sh`, `Updates.swift`, `ConnectionSettings.swift`, `release-update.sh`. Не публикуйте форк с feed оригинального проекта. Для обычной локальной сборки приватный ключ не нужен: он нужен только издателю обновлений.

Приложение пока имеет ad-hoc подпись, без Developer ID и нотариального заверения Apple. Подлинность обновлений обеспечивает отдельная Ed25519-подпись Sparkle. Это не заменяет заверение Apple для первого запуска скачанного приложения. В этой версии автоматическая установка без подтверждения отключена, системная телеметрия Sparkle выключена.
